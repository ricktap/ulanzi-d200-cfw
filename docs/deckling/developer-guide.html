Das Modell

Nur Plugins enthalten Code. Sie veröffentlichen Werte und bieten Aktionen an. Icon Sets und Themes sind reine Daten, die der Kern beim Zeichnen liest.

BegriffBedeutungGehört zu
SignalEin benannter Wert über die Zeit, zum Beispiel com.ricktap.hue:lamp.colorPlugin oder Kern
AktionEtwas, das ein Plugin tun kann, zum Beispiel com.ricktap.hue:lamp.togglePlugin oder Kern
Interface (Rolle)Eine Liste benannter Eigenschaften mit Typ, ohne DatenKern oder Plugin
AppErfüllt Interfaces, indem sie Signale und Einstellungen auf deren Eigenschaften abbildetPlugin
IconSVG mit benannten Teilen plus Bindungsdatei. Nennt seine RollenIcon Set
Theme VariableEin benannter Wert für das Aussehen, fest oder an ein Signal gebundenTheme
EinstellungParameter einer App je TasteApp, gespeichert an der Taste

Namensräume und Rechte

Die Paket ID in umgekehrter Domain Schreibweise ist der Namensraum: com.ricktap.bambu:ams.casing. Namen ohne Präfix gehören dem Kern, etwa accent, time.second oder toggle.

PaketDarf definierenDarf lesen
PluginSignale, Aktionen, Interfaces, Apps und Icons, nur im eigenen Namensraumeigene Einstellungen
Icon SetIcons im eigenen NamensraumInterfaces, Signale und Theme Variablen aus allen Namensräumen
ThemeVariablen in allen NamensräumenSignale aus allen Namensräumen

Zwei Folgen sind wichtig. Plugins setzen keine Farben, auch nicht zur Laufzeit. Und ein Plugin hört nie selbst auf Tasten: Den Tastendruck erkennt der Kern und ruft die Aktionen, die an der Taste eingetragen sind.

Die Bindungssprache

Ein Wert kommt immer aus einer von wenigen Quellen. Die Sprache ist absichtlich klein und gilt gleich in Apps, Icons und Themes.

SchlüsselWirkungErlaubt in
bindliest ein Signal. Platzhalter wie {unit} werden aus den Einstellungen der Taste gefülltApp, Icon, Theme
configliest eine Einstellung der TasteApp
propliest eine Eigenschaft eines Interfaces, zum Beispiel toggle.onIcon
toneliest eine Theme Variable, zum Beispiel accentIcon
stepswählt nach einer Zahl aus einer Liste, reihumüberall
mapwählt nach einem benannten Wert aus einer Tabelleüberall
prefix, suffixsetzt Text vor und hinter den Wertüberall
fallbackErsatz, wenn der Wert fehlt. Pflicht bei prop, bind und bei Variablen außerhalb der Kernvariablenüberall

Mehr soll die Sprache nicht können. Wer Bedingungen oder Formeln braucht, rechnet im Plugin und veröffentlicht das Ergebnis als Signal.

Beispiel 1: Hue Lampe

Zeigt den Kern des Modells. Eine App erfüllt mehrere Interfaces, und der Nutzer wählt ein Icon, das mindestens eines davon versteht. Tippe auf die Taste, um die Lampe zu schalten, und wechsle darunter das Icon.

Was du mitnimmst

  • Kein Icon nennt ein Signal der App. Die gelbe Markierung kommt nur im Plugin und in der App vor.
  • Die Glühbirne aus dem fremden Set funktioniert mit jeder App, die toggle oder rgb erfüllt.
  • button erfüllt jede App von selbst. Deshalb passt die Tischlampe als reines Symbol überall.

Beispiel 2: Uhr mit Einstellung

Zeigt Einstellungen einer App. Das Feld display ist vom Typ select mit festen Werten. Die App reicht es als Eigenschaft clock.style an das Icon weiter, genau wie ein Signal.

Was du mitnimmst

  • Der Konfigurator baut das Auswahlfeld aus dem Schema in config.
  • Die Einstellung gehört zur Taste. Zwei Uhren können verschieden eingestellt sein.
  • Das Icon entscheidet mit map, welche Teile sichtbar sind. Die Zeiger dreht es mit prefix und suffix um einen Winkel, den der Kern als Signal liefert.

Beispiel 3: Bambu Lab AMS

Zeigt ein eigenes Interface, eine Einstellung mit Werten vom Plugin und Theme Variablen im Namensraum des Plugins. Wähle das Gerät, wechsle das Theme und schalte Auflagen dazu.

Was du mitnimmst

  • Zwei Geräte sind dieselbe App mit anderer Einstellung. Der Platzhalter {unit} in bind wählt die Signale.
  • Die LED fragt nach com.ricktap.bambu:ams.led. Night Signal setzt sie fest auf Blau, Bernstein bindet sie an time.second und lässt sie zwischen Rot und Grün wechseln.
  • Das Gehäuse fragt nach com.ricktap.bambu:ams.casing. Kein volles Theme setzt sie, also greift der fallback. Die Auflage setzt sie.
  • Regenbogen und Hue Sync sind keine Sonderfunktion. Es sind Themes vom Typ partial, die accent an ein Signal binden. Die Auflagen gelten für alle Tasten auf dieser Seite.

Beispiel 4: Musik

Zeigt Aktionen. Die App belegt Drücken und Lang drücken vor. Der Kern erkennt den Tastendruck, schlägt in der Belegung nach und ruft die Aktion im Plugin.

Was du mitnimmst

  • on in der App ist nur eine Vorbelegung. Auf der Taste lassen sich die Aktionen danach frei ändern.
  • Das Plugin ändert seinen Zustand und veröffentlicht neu. Das Icon folgt von selbst, weil es gebunden ist.
  • Der Ring trägt die Farbe des Covers. Mit der Auflage Regenbogen aus Beispiel 3 ändert sich nur der fallback, weil das Icon hier bewusst die Farbe der App vorzieht.

Signale live

Alles, was Kern und Plugins auf dieser Seite gerade veröffentlichen. Im Konfigurator gibt es dieselbe Ansicht.

    Interfaces ändern

    Fremde Icons zeichnen gegen dein Interface. Benennst du eine Eigenschaft um, lesen sie ins Leere. Drei Regeln verhindern das.

    • Ein veröffentlichtes Interface ändert sich nicht mehr. Eigenschaften hinzufügen ist erlaubt, weil jedes Icon mit fehlenden Werten umgehen muss.
    • Umbenennen, Entfernen oder ein anderer Typ ist ein neues Interface mit Version im Namen, zum Beispiel com.ricktap.hue:rgb_light@2. Ohne Zusatz ist Version 1 gemeint.
    • Deine App darf alte und neue Version zugleich erfüllen. Das ist nur ein weiterer Block in implements. Alte Icons laufen weiter, solange du die alte Version mitführst.

    Ein Icon Set legt eine Kopie jedes fremden Interfaces bei, gegen das es gezeichnet wurde, im Ordner interfaces/. Der Kern vergleicht beim Laden und meldet, wenn ein Icon für eine andere Version gebaut wurde. Liest ein Icon eine Eigenschaft, die es nicht mehr gibt, greift der fallback. Das Icon ist dann ärmer, aber nicht kaputt.

    Zum Prüfen gibt es die Icon Werkbank. Sie lädt Bindungsdatei, SVG und Interface, baut Regler aus den Typen und meldet jede gelesene Eigenschaft, die das Interface nicht kennt.

    Referenz

    Typen

    Signale und Eigenschaften von Interfaces sind typisiert. Werkzeuge und Konfigurator wissen damit, wie ein Wert darzustellen ist.

    TypWertRegler in der Werkbank
    flagan oder ausSchalter
    percent0 bis 100Schieber
    numberZahlSchieber
    colorFarbeFarbwähler
    textTextTextfeld

    Einstellungen eines Plugins

    Ein Plugin beschreibt seine Einstellungen als config im Manifest, mit demselben Schema wie die Einstellungen einer App. Der Konfigurator zeigt die Felder in der Ansicht Pakete direkt am Plugin. Typen sind text, toggle, select und number. Die Einstellungen des Plugins core sind die globalen Einstellungen des Decks. Ein eigenes Optionsmenü gibt es nicht.

    Manifest eines Plugins

    Jedes Paket hat eine deckling.json. Der Typ ist plugin, iconset oder theme. Ein Plugin darf ein Icon Set einbetten. Es hat dasselbe Format wie ein eigenständiges Set.

    
  
    Was der Code eines Plugins darf
    
  
    
    
    AufrufZweck
    
    
    core.publish(name, wert)veröffentlicht ein Signal im eigenen Namensraum
    
    
    core.onAction(name, fn)nimmt eine Aktion entgegen
    
    
    core.provideOptions(name, fn)liefert Werte für ein Auswahlfeld zur Laufzeit
    
    
    core.every(ms, fn)Zeitgeber in dieser Demo
    
  
    
  
    Signale des Kerns
    
  
    time.clock, time.second, time.tick, time.hour_angle, time.minute_angle. Geplant sind key.index, key.column und key.row, die je Taste verschieden sind. Damit lässt sich eine Welle über das Deck beschreiben.
    
  
    Primitive Interfaces
    
  
    
  
    Vertrag für das SVG eines Icons
    
  
      
    
    • Teile heißen über data-part. Ein Element darf mehrere Namen tragen, durch Leerzeichen getrennt.
      • 
    
    • Keine festen Farben. Farben kommen aus tone, prop oder bind.
      • 
    
    • progress füllt eine Linie anteilig von 0 bis 100. Das Element braucht pathLength="100".
      • 
    
    • visible blendet ein Teil ein oder aus. text setzt den Inhalt eines Textelements.
      • 
    
    • Jeder andere Schlüssel wird als SVG Attribut gesetzt, zum Beispiel fill, stroke, cx oder transform.
      • 
  
    
  
    Theme
    
  
    Ein Theme vom Typ full setzt alle Kernvariablen: background, base, muted, accent. Genau eines ist aktiv. Themes vom Typ partial setzen einzelne Variablen und liegen als Auflagen darüber. Setzen zwei dieselbe Variable, gewinnt die untere in der Liste.
    
  
    Belegung einer Taste in deck.json
    
  
    
  
    Oben in der Datei stehen das volle Theme und die geordnete Liste der Auflagen.
    
  
    

  
    Checklisten
    
  
    Ich baue ein Plugin
    
  
      
    
    • Signale nach dem benennen, was sie sind, nicht nach dem, was ein Icon gern hätte.
      • 
    
    • Jede App erfüllt neben ihrem eigenen Interface so viele Primitive wie sinnvoll. Dann passen fremde Icons sofort.
      • 
    
    • Gibt es mehrere Geräte, bekommt die App eine Einstellung und bindet über einen Platzhalter.
      • 
    
    • Ein eingebettetes Icon je App mitliefern. Es ist der Standard, bis der Nutzer ein anderes wählt.
      • 
    
    • Keine Farben setzen und nicht auf Tasten hören.
      • 
    
    • Signale mit Typ anmelden. Ein veröffentlichtes Interface nicht mehr ändern, sondern eine neue Version anlegen.
      • 
  
    
  
    Ich baue ein Icon Set
    
  
      
    
    • Gegen Interfaces zeichnen, nie gegen Signale einer bestimmten App.
      • 
    
    • Jede Bindung mit fallback versehen. Für jede genannte Rolle prüfen, ob das Icon nur mit deren Eigenschaften ordentlich aussieht.
      • 
    
    • Farben über tone holen, damit das Icon jedem Theme folgt.
      • 
    
    • Das Icon in der Werkbank gegen jede genannte Rolle prüfen und eine Kopie fremder Interfaces beilegen.
      • 
  
    
  
    Ich baue ein Theme
    
  
      
    
    • Für ein volles Theme alle vier Kernvariablen setzen.
      • 
    
    • Für einen Effekt ein Theme vom Typ partial bauen, das nur die betroffenen Variablen setzt.
      • 
    
    • Bei jeder Bindung an ein Signal eines Plugins einen fallback nennen, falls das Plugin fehlt.

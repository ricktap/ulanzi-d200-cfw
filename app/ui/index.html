    How Home Assistant uses it

    The password is stored in deck.json, readable only by your user.

    Meeting controls (mute, camera, hand, leave)

    In Teams: Settings → Privacy → Manage API → enable the third-party app API. The first time you press a Teams key during a meeting, Teams asks to allow "D200 Deck".

    Presence (available ↔ unavailable)

    Presence goes through Microsoft Graph and needs a sign-in. Register an app in Microsoft Entra: App registrations → New, single tenant, then under Authentication enable Allow public client flows, and under API permissions add Microsoft Graph delegated Presence.ReadWrite. Your organisation may have to approve it. Set Tenant to your company domain or tenant ID (needed for single-tenant apps).

    Save the client ID before signing in. Tokens are kept in teams-auth.json, readable only by you.

    Cards on the wide key

    The wide key shows one thing at a time: its default content (set by clicking it in the grid), or a card. Priority: critical › meeting › printer › push › email. Ordinary cards stay 8 s; critical ones until you press the key.

    Mail and meetings come from Microsoft 365 (the Teams sign-in). The printer reads JSON from d200/printer, e.g. from a Home Assistant automation: {"state":"printing","percent":62,"remaining_min":18,"name":"Bambu X1C","job":"bracket"}.

    Screensaver

    A key press wakes the deck without running that key's action. Critical alerts wake it; other cards wait behind a small dot. Each frame is sent over USB, so keep FPS modest.

    Palette

    Semantic colours for widgets and cards (active, info, attention, error) and the widget surface. Per-widget values below win over these.

    Unset values follow the palette. Error states keep their warning colour.
